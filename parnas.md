Parnas Reflection
Question 1
One important lesson from the Parnas paper is information hiding. Parnas argues that software should be organized into modules that hide implementation details from other parts of the program. This idea remains relevant today because it makes software easier to maintain and update without affecting unrelated components.

Question 2
The paper was written in 1972, when software development practices and tools were much more limited. Today, programmers use version control systems such as Git, automated testing, and modern development environments. These tools make collaboration and maintenance much easier than they were when the paper was written.

Question 3
I have used modularity in programming courses by separating programs into multiple classes and methods. Instead of placing all code in one file, different components were responsible for different tasks. This made the code easier to read, debug, and modify.
